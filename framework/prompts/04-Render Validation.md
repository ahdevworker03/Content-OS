# 04 — Render Validation

## Purpose

Validate that the structured content generated by the Post Content Builder renders correctly inside the React carousel renderer. This workflow confirms that `production/workspace/carousel.json` is structurally sound, every slide renders without error, and the carousel is ready for export. It performs validation only — it does not generate content, modify data, or produce assets.

---

## Scope

This workflow begins after the Post Content Builder has successfully generated `production/workspace/carousel.json`.

It ends when the carousel has either:
- passed validation and is confirmed render-ready, or
- a validation report has been produced describing all issues found.

---

## Required Reading

- `framework/prompts/README.md` — Prompt system architecture, workflow boundaries, global execution rules.
- `framework/model/Content Model.md` — Canonical JSON schema that `carousel.json` must conform to.

No other Framework documents are required for this workflow. Strategy, format, and brand documents are not consulted during rendering validation.

---

## Inputs

- **`production/workspace/carousel.json`** — The canonical structured data output from the Post Content Builder. This is the single source of truth for rendering.
- **React renderer** — The carousel rendering application in `production/renderer/`. It reads the JSON and renders each slide as a visual component.
- **Renderer configuration** — Any settings the renderer requires to load and display the carousel correctly.
- **Validation tooling** — Any existing validation scripts, schema validators, or rendering checks available in the repository.

---

## Outputs

The workflow produces exactly one of the following outcomes:

1. **Validation successful.** A confirmation that the carousel is render-ready — all slides rendered without errors, the JSON structure is valid, and the carousel can proceed to export.

2. **Validation report.** A description of all detected issues that must be resolved before export. The report includes what was checked, what failed, and where the problem is located (specific slide, field, layout, or reference). It does not include fixes.

The workflow does not modify `carousel.json`. It does not automatically fix issues.

---

## Success Criteria

Validation passes when all of the following are true:

- **JSON successfully loaded.** `carousel.json` is valid JSON and can be parsed without errors.
- **Content Model structure accepted.** The JSON conforms to the Content Model schema defined in `framework/model/Content Model.md`. All required blocks are present and correctly typed.
- **Every slide rendered successfully.** The renderer processed each slide and produced output without exceptions.
- **No missing layouts.** Every slide references a layout type that the renderer supports.
- **No missing required fields.** Every slide contains the fields required by its layout type.
- **No rendering errors.** The renderer completed without JavaScript errors, React errors, or failed component renders.
- **No unsupported layout types.** All layout values in the JSON match known renderer layouts.
- **No broken assets or references.** Any asset references (images, icons) in the JSON resolve correctly within the renderer context.
- **Carousel confirmed ready for export.** All slides are visually complete and structurally valid.

---

## Workflow

1. **Load `carousel.json`.** Read `production/workspace/carousel.json` and parse it. Verify that it is valid JSON. If parsing fails, produce a validation report and stop.

2. **Validate against the Content Model.** Check that the loaded JSON conforms to the schema in `framework/model/Content Model.md`. Verify that all required blocks (identity, trigger, metadata, variants) are present and correctly typed. If validation fails, produce a report describing every schema violation and stop.

3. **Launch the React renderer.** Start the renderer application with the appropriate configuration. Load `carousel.json` into the renderer's data pipeline.

4. **Render every slide.** Instruct the renderer to process every slide defined in the carousel data. Ensure each slide is rendered individually, not skipped or batched silently.

5. **Validate the rendered output.** For each rendered slide, verify:
   - The slide was rendered without JavaScript or React errors.
   - The slide content matches the corresponding data in `carousel.json`.
   - The layout type is supported and applied correctly.
   - All text, fields, and references are present in the rendered output.
   - No slides are empty, truncated, or missing critical content.

6. **Detect and collect rendering problems.** If any slide fails to render, produces an error, or is visually incomplete, record the issue. Capture the slide number, the field or layout involved, and the nature of the problem.

7. **Produce the outcome.** If all slides pass validation, confirm that the carousel is render-ready. If any issues were found, produce a validation report listing every detected issue. Do not modify `carousel.json` or the renderer.

---

## Constraints

- Never modify `carousel.json`. This workflow is read-only with respect to content data.
- Never rewrite or adjust content. Content changes belong to workflow 03.
- Never redesign layouts, change slide order, or alter the renderer.
- Never export PNGs, screenshots, or visual assets. Export belongs to workflow 05.
- Never update repository files, archive content, or modify the posted-titles index. Those responsibilities belong to workflow 06.
- Never skip validation steps. Every slide and every required field must be checked.
- Never report a slide as passing if it cannot be verified. When in doubt, report the uncertainty.

---

## Completion

This workflow ends immediately after either outcome is delivered:
- A confirmation that the carousel is render-ready, or
- A complete validation report describing all issues found.

No further workflows are triggered. The agent stops.
