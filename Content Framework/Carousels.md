# Carousels

Carousels are the main educational documentation.
They should be structured, reflective, and useful enough that people see the journey.

Carousels are best for:

- Concepts (What I learned)
- Explanations (How I understood it)
- Comparisons (What I chose)
- Reflections (Why it was hard)
- Thought processes
- Lessons from learning and building

---

## 1) Educational Documentation

### Purpose

Explain a concept from a student's perspective.

### Structure (Mandatory)

1. **Slide 1: Hook** (The "Facepalm" or "Aha!" moment)
2. **Slide 2: The Trigger** (The specific bug, lecture, or project feature that forced me to learn this)
3. **Slides 3-X: Body** (Explain the concept using "I found" logic)
4. **Slide X-1: Project Bridge** (A snippet of the "Car Rental System" showing this concept in action)
5. **Slide X: Community CTA** (Beginner-friendly question: "What part of this is still confusing?")

### Possible ideas

- Programming fundamentals
- Computer Science basics
- Operating systems
- Linux concepts
- Git and GitHub
- Web development basics
- Databases
- API concepts
- Authentication
- CRUD
- State and props
- Browser behavior
- Deployment basics
- Development tools
- Software engineering fundamentals

### Content style

These posts should:

- Start with a personal hook
- Define the concept in plain language (as I understood it)
- Use examples from my own code
- Avoid unnecessary jargon
- Focus on clarity over complexity
- End with a question for fellow learners

### What to avoid

- Sounding like a teacher ("You should...")
- Too much theory with no application
- Overcomplicated explanations
- Trying to sound more advanced than necessary
