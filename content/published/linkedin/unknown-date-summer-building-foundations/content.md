# After my first year of Computer Science, I realized there's a difference between preparing to build and actually building.

After my first year of Computer Science, I realized there's a difference between preparing to build and actually building.

The first year taught me HTML, CSS, JavaScript, and TypeScript. I built projects, published a portfolio, and shipped real work. But every time I started a new project, I hit a wall. Not because I didn't know enough — but because I was still at the beginning of the road.

The moment I noticed the real pattern was when summer started. I opened YouTube, and within a week I had collected React, Next.js, Linux, Docker, Git, and backend courses. My to-learn list was longer than my shipped projects. I wasn't deciding what to learn — I was avoiding the discomfort of not knowing where to start.

That's when I realized: the problem wasn't information. It was action.

So I made one decision: everything I learn this summer has to be tied to a real project.

- React, because most ideas I want to build need it.
- TypeScript, because every project shows me how much I still don't fully understand.
- Git, because I want to work the way real teams do.
- Linux, because I want to understand the environment my code runs on.

Not to collect technologies. To build more.

I'm guessing I'll spend hours on bugs. I'll probably rewrite the same code twice. But I've learned that type of work teaches me more than any tutorial ever could.

In three months, either I'll have projects I'm proud of, or a longer list of courses I planned to start. I know which one I'm choosing.
